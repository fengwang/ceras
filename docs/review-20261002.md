# Ceras: sharded review and modernization plan

Implementation follow-up: [repairs and validation evidence](implementation-20261002.md), [migration guide](migration-20261002.md). The findings below describe the reviewed main-branch snapshot.

Review date: 2026-10-02. Reviewed local `main` at **`48fe97c1ef30181cffa0446af8f6831140c9963d`**. The working branch, `review/20261002`, pointed to that same commit. No remote fetch was performed. This report reviews the library, not a proposed implementation diff.

The immediate priority is to repair memory ownership, input validation, and differentiation. Changing the language standard alone will not make this library safe. The review confirmed memory corruption, incorrect gradients, a dangling-reference design, and failure to link an ordinary program with two translation units. Existing utility tests pass despite those failures.

Accepted, deduplicated findings: **18 High, 13 Medium, 1 Low** (32 total). F27's High severity is conditional on overlapping CUDA calls; no Critical finding is established.

“Bug-free” cannot be established by this review or promised by a migration. The executable target is: close the accepted findings, establish explicit contracts, and require reproducible numerical, sanitizer, integration, and resource-lifetime gates for every supported configuration.

## Scope and review method

Six independent, read-only reviewers inspected tracked first-party code. They did not edit source, tests, or temporary files. The coordinator checked their claims against source and compiled small probes into `/tmp/ceras-review-20261002`; the only repository artifact added is this report. Existing untracked binaries, generated documentation, third-party directories, and duplicate trees were excluded and left untouched.

The requested `docs/agent_workflow/prompts/sharded_review.md` does not exist in this checkout or the reviewed commit. The review followed the rules in the request. A sibling-workspace copy of that prompt was read for format guidance; it adds the same evidence, contract, impact, fix, confidence, and deduplication requirements. It was not treated as a repository-specific contract.

| Shard | Targeted scope | Canonical findings / corroboration |
| --- | --- | --- |
| Correctness | Tensor reductions, graph execution, activations, losses, optimizer recurrences | F09–F17; F16 corroborated by architecture |
| Readability/simplicity | Public API usability, exception specifications, reproducibility | F21–F23; ordering cleanup in the backlog |
| Security/safety | Allocation, arithmetic overflow, parsers, image I/O, lifetimes | F01–F08; corroborated F24 |
| Tests | Actual CI entry points, assertions, backend tests, build targets | F28–F31 |
| Architecture/maintainability | Header linkage, compiled-model lifetime, global ownership, API drift | F18–F20, F32; corroborated F16 |
| Performance | Thread creation, GEMM dispatch, CUDA scratch lifetime, calibration | F24–F27 |

Review concentrated on high-fanout boundaries rather than every historical example: tensor storage → views/operations → forward/backward state → optimizer state, plus external data → allocation/copy and backend dispatch. Vendored implementation internals, exhaustive convolution/recurrent derivatives, all experimental utilities, GPU execution, and full training convergence were not audited.

Findings are deduplicated by failure mechanism. Critical/High findings do not require consensus when evidence is concrete. Every accepted Medium below has a direct source counterexample, compiler diagnostic, dry-run result, or runtime reproduction; none is based only on preference. No Critical finding is claimed: deployment/exploitability evidence would be needed to justify that escalation. “Contract: inferred” explicitly distinguishes an expected invariant from a written project promise.

## Accepted findings

### F01 — High: allocator reclamation keeps freed addresses available for reuse

- **Reviewers / confidence:** Safety; coordinator reproduced. High.
- **Evidence:** `include/utils/cached_allocator.hpp:99–108` frees reserved blocks without removing their map entries. Lines 46–52 subsequently return an entry as live storage; lines 92–95 can free it again. Allocate four floats, deallocate them, call `gc()`, then allocate four floats: ASan reports heap-use-after-free in `cached_allocator::allocate` at line 144. The normal allocation-failure retry also invokes `gc()` at lines 64–67.
- **Contract:** Inferred allocator invariant: a reusable entry must own a live allocation, and each allocation is freed once.
- **Smallest safe fix:** Erase each entry as it is freed; propagate `bad_alloc` when allocation cannot recover, rather than returning null after a disabled assertion. Add deterministic reclamation and allocation-failure tests. Disable this allocator by default until those tests pass.

### F02 — High: unchecked shape/byte multiplication underallocates tensors

- **Reviewers / confidence:** Safety; coordinator source check. High.
- **Evidence:** `include/tensor.hpp:80–86,337` multiply extents without overflow checks. `include/utils/cached_allocator.hpp:143–144` computes `n*sizeof(T)` without a bound check; `include/utils/vector.hpp:43–48` fills the original element count. On this 64-bit platform, `tensor<double>({ULONG_MAX/sizeof(double)+1})` wraps the requested byte count to zero but retains the enormous fill count.
- **Contract:** Inferred storage invariant: logical size and allocation size must agree without arithmetic wraparound.
- **Smallest safe fix:** Centralize checked extent products and checked element-to-byte conversion before allocation, including backend dimensions and offsets. Reject oversized requests with a defined error; use `std::size_t` for sizes and checked narrowing at BLAS/CUDA boundaries. Test the maximum accepted size and values immediately beyond it without attempting huge allocations.

### F03 — High: release-mode deserialization writes beyond tensor storage

- **Reviewers / confidence:** Safety; coordinator reproduced. High.
- **Evidence:** `include/tensor.tcc:1238–1242` sizes the destination from its shape and copies every parsed value. Its only count check is `better_assert`; `include/utils/better_assert.hpp:12–17` does not abort under `NDEBUG` (`include/config.hpp:30–33`). Input `"1\n1 2 3\n"` produces an ASan heap-buffer-overflow. The same release-only validation pattern lets `session::restore_original` dereference an unknown-ID lookup at `include/session.hpp:160–164`.
- **Contract:** The serialized shape/data format requires matching counts; inferred malformed-input safety and valid lookup invariants.
- **Smallest safe fix:** Unconditionally validate syntax, rank, extent products, payload counts, stream state, and variable IDs. Parse into temporary state and commit only after successful validation. Return an error or throw; retain assertions only for internal invariants. Add `NDEBUG` parser tests and bounded fuzzing.

### F04 — High: malformed IDX datasets overwrite memory

- **Reviewers / confidence:** Safety; coordinator source check. High.
- **Evidence:** `include/dataset.hpp:47–49` allocates `(file_size-16)/784` images but copies the entire remaining payload. A 16+784+1-byte file copies 785 bytes into 784 bytes. Line 60 uses an arbitrary label byte as a ten-column index; label 255 exceeds the row. Fashion-MNIST duplicates the defects at lines 118–120 and 131. Files shorter than their headers also underflow size calculations.
- **Contract:** The documented image shape and label range at lines 17–18 and 76–77; inferred input-validation boundary.
- **Smallest safe fix:** Share one checked IDX parser. Validate magic, dimensions, sample count, header length, exact payload length, image/label count agreement, and labels below ten before allocating or copying. Test truncation, extra bytes, inconsistent headers, and invalid labels.

### F05 — High: grayscale resize describes twice the actual buffer size

- **Reviewers / confidence:** Safety; coordinator reproduced. High.
- **Evidence:** `include/utils/imageio.hpp:15,23` allocates one element per rank-two pixel but passes two channels to STB. Resizing `{2,2}` to `{4,4}` triggers an ASan out-of-bounds read through this call. Output rank is also unchecked before `output_shape[2]` at line 18.
- **Contract:** Inferred image-buffer extent invariant; line 23 explicitly identifies the branch as grayscale.
- **Smallest safe fix:** Use one channel for rank-two images; validate both ranks, dimensions, channels, and conversion to STB's integer parameters. Check the resize result. Cover rank-two grayscale, supported color channels, and invalid shapes under ASan.

### F06 — High: HDR writing interprets byte pixels as floats

- **Reviewers / confidence:** Safety; coordinator source check. High.
- **Evidence:** `include/utils/imageio.hpp:74–75` casts image storage to `float const*`. `imwrite` passes byte tensors directly at lines 86–88 and converts larger pixel types to bytes at lines 94–96. Consequently, ordinary HDR writes supply one byte per component to a function that reads a float per component, exceeding the backing allocation.
- **Contract:** Inferred typed-storage and writer read-boundary invariants.
- **Smallest safe fix:** Dispatch HDR before byte normalization and supply real float storage. Constrain direct writer overloads to their supported pixel types. Test byte-to-HDR conversion and native float HDR with tiny fixtures; inspect decoded values as well as sanitizer results.

### F07 — Medium: the shape allocator does not meet allocator requirements

- **Reviewers / confidence:** Safety; coordinator source check. High; strong source evidence.
- **Evidence:** `include/utils/buffered_allocator.hpp:35–46` passes a byte count to `std::allocator<T>::allocate`, which expects an element count, but deallocates with `n` at line 64. Its inline `std::array<std::byte,...>` at line 68 does not guarantee `T` alignment, and each small allocation returns the same address at line 37. `tensor::shape_` uses this allocator at `include/tensor.hpp:52`; exceeding its inline capacity takes the mismatched-count path.
- **Contract:** Standard allocator count, alignment, and distinct-live-allocation requirements. The comment restricting use to tensors does not remove these requirements.
- **Smallest safe fix:** Replace this shape allocator with `std::allocator` first. If measurements justify inline storage, use a container designed for it, with tested move/growth semantics. Do not implement small-vector storage by handing `std::vector` an allocator-owned byte array.

### F08 — Medium: custom vector mutation breaks ownership and exception safety

- **Reviewers / confidence:** Safety; coordinator source check. High; strong source evidence.
- **Evidence:** `include/utils/vector.hpp:94–100` clears existing storage and sets positive `size_` before allocation succeeds. A thrown allocation leaves `{size>0,data=nullptr}`, later deallocated at lines 80–83. Move assignment at lines 34–40 overwrites the previous pointer without releasing it. Stateful allocator ownership is also absent: allocation/deallocation each construct a fresh allocator.
- **Contract:** Inferred RAII/basic exception guarantee: a failed operation leaves a valid, destructible owner; move assignment releases previous ownership.
- **Smallest safe fix:** Prefer standard owning storage. As a transitional patch, allocate before committing metadata, release old storage after success, handle self-move, and preserve allocator identity. Add a throwing allocator test and move-assignment lifetime accounting.

### F09 — High: reused graph nodes lose backward intermediates

- **Reviewers / confidence:** Correctness; coordinator reproduced. High.
- **Evidence:** `include/operation.hpp:58–84,147–175,202–206` shares node state/identity but keeps saved input tensors in each wrapper. A cache hit restores output only. Constructing `r=relu(x); loss=sum_reduce(r+r)` before execution leaves one copy's saved input empty. Backward produced a UBSan null load and ASan SEGV in the release probe through `include/activation.hpp:308`.
- **Contract:** Inferred DAG/autodiff invariant: every backward edge must see the forward intermediates for the same execution.
- **Smallest safe fix:** Store a complete forward record in shared node/execution state, identified by execution generation. A cache hit must obtain that record. Test diamond graphs, repeated runs with new inputs, and multiple consumers with different upstream gradients.

### F10 — High: softmax backward omits off-diagonal Jacobian terms

- **Reviewers / confidence:** Correctness; coordinator reproduced. High.
- **Evidence:** `include/activation.hpp:108–113` computes `g_i*p_i*(1-p_i)`. With logits `[0,0]` and upstream `[1,1]`, the probe returned `[0.25,0.25]`; the derivative of the constant sum of softmax outputs must be `[0,0]`.
- **Contract:** Named softmax operation and inferred chain rule.
- **Smallest safe fix:** Per final-axis row, compute `s=sum(g*p)` and `dx=p*(g-s)` in independent output storage. Assert the constant-sum property and compare arbitrary upstream vectors against central differences.

### F11 — High: mean backward divides by the wrong element count

- **Reviewers / confidence:** Correctness; coordinator reproduced. High.
- **Evidence:** Forward divides by total size at `include/tensor.tcc:775–779`; backward divides by the first extent, or one for rank-one input, at `include/operation.hpp:972–975`. Shape `{2,3}` produced six gradients of `0.5`, instead of `1/6`. Composed MSE/MAE inherit the inconsistency.
- **Contract:** Explicit “across all dimensions” documentation at `include/operation.hpp:949`.
- **Smallest safe fix:** Divide by `input.size()` and define empty-input behavior. Coordinate this with loss/optimizer normalization in F12 so training does not acquire an additional batch-size divisor.

### F12 — High: cross-entropy backward does not differentiate its averaged forward result

- **Reviewers / confidence:** Correctness; coordinator source check. High.
- **Evidence:** `include/loss.hpp:81` averages over the first extent; lines 93,104–111 return `grad[0]*(softmax-target)` without that divisor. For two identical binary-class rows with zero logits, each row's logit gradient is approximately `[-0.5,0.5]` instead of `[-0.25,0.25]`.
- **Contract:** Inferred chain rule for the scalar returned by forward, including weighted/composed losses.
- **Smallest safe fix:** Apply the same reduction in backward and define an explicit `none/sum/mean` policy. Audit optimizer constructors such as `include/optimizer.hpp:42`, which independently divide learning rate by batch size. Fix the combined convention with documented migration behavior and batch-size invariance tests.

### F13 — High: ELU backward uses the upstream gradient as the exponential argument

- **Reviewers / confidence:** Correctness; coordinator source check. High.
- **Evidence:** `include/activation.hpp:468–473` returns `alpha*exp(g)` for negative input. At input `-1`, alpha `1`, and upstream zero, it returns `1`; the chain rule requires zero.
- **Contract:** ELU's documented forward formula at line 445 and the chain rule.
- **Smallest safe fix:** Return `g*alpha*exp(input)` on the negative branch, using distinct result storage. Test zero, negative, and scaled upstream gradients away from the branch boundary.

### F14 — High: GELU backward ignores the forward input

- **Reviewers / confidence:** Correctness; coordinator source check. High.
- **Evidence:** `include/activation.hpp:600–604` computes `_dgelu(grad)` rather than `grad*_dgelu(input)`. Zero upstream becomes `0.5`. The helper at line 585 also places the cubic derivative multiplier inside the `sech²` argument and lacks a required factor of `0.5` in its second term.
- **Contract:** The documented GELU approximation at lines 556–557 and the chain rule.
- **Smallest safe fix:** Differentiate the actual tanh approximation correctly, then multiply by upstream gradient into fresh storage. Verify central differences over negative/positive inputs and upstream linearity.

### F15 — High: Adadelta aliases its independent accumulators

- **Reviewers / confidence:** Correctness; coordinator source check. High.
- **Evidence:** `include/optimizer.hpp:207–211` creates two slots but binds both `moments` and `delta` to slot zero. The ratio at line 229 is therefore one, and line 236 updates the same accumulator again.
- **Contract:** The separate moment/delta recurrence explicitly present at lines 226–236; named Adadelta semantics.
- **Smallest safe fix:** Bind `delta` to `contexts[1]`. Add a hand-calculated multi-step scalar recurrence, including a change in gradient magnitude; a decreasing-loss demonstration is insufficient.

### F16 — High: switching optimizers can read beyond shared state

- **Reviewers / confidence:** Correctness and architecture. High; independent corroboration and coordinator source check.
- **Evidence:** Optimizer contexts belong to each variable (`include/variable.hpp:27–32,120–123`). SGD creates one slot at `include/optimizer.hpp:57–58`. Adam initializes only an empty vector at lines 278–284 and unconditionally accesses slot one at line 286. SGD followed by Adam on the same variable leaves only one slot. Equal-sized state from other optimizers can also carry incompatible meanings.
- **Contract:** Inferred memory-safety and optimizer-state isolation invariants.
- **Smallest safe fix:** Introduce typed state owned by the optimizer instance, keyed by variable identity. A transitional guard must validate optimizer identity, slot count, and shapes and explicitly reset/reject incompatible state; merely resizing the vector does not address semantic contamination.

### F17 — Medium: maximum reduction returns a positive value for negative inputs

- **Reviewers / confidence:** Coordinator extension of correctness shard. High; runtime counterexample.
- **Evidence:** `include/tensor.tcc:1190` initializes a maximum with `numeric_limits<T>::min()`. For floating types this is the smallest positive normal value. Reducing `[-2,-1]` returned `1.17549e-38` instead of `-1`.
- **Contract:** Inferred maximum-reduction semantics.
- **Smallest safe fix:** For nonempty reductions initialize from an actual element, or use a correctly specified identity (`lowest()` for finite-only inputs, negative infinity where supported and required). Define empty, NaN, and infinity behavior and test it explicitly.

### F18 — High: public headers violate the one-definition rule

- **Reviewers / confidence:** Architecture; coordinator reproduced. High.
- **Evidence:** `include/includes.hpp:55–60` enables STB implementation definitions in every translation unit. Compiling and linking two otherwise empty files that include `ceras.hpp` fails with multiple definitions of `stbi_failure_reason`, `stbi_image_free`, `stbi_load`, and others. STB itself describes the one-implementation-unit rule at `include/utils/3rd_party/stb_image.h:4–6`.
- **Contract:** `ReadMe.md` advertises a header-only library; ordinary multi-translation-unit integration must link and obey the C++ one-definition rule.
- **Smallest safe fix:** Isolate image implementations behind an opt-in implementation translation unit or small compiled image-I/O target, keeping core headers independent. If preserving a fully header-only distribution, use a deliberate linkage-safe integration and test its size/state consequences. Add a two-TU link-and-run test before refactoring header boundaries.

### F19 — High: copying/moving a compiled model leaves a reference into its source

- **Reviewers / confidence:** Architecture; coordinator reproduced reference identity. High.
- **Evidence:** `include/model.hpp:80–85` stores `loss_` and initializes its optimizer with a reference to that member. Optimizers retain `Loss&` (`include/optimizer.hpp:31,253`). Implicit copy/move preserves that reference. The copy probe printed `source loss=1 destination loss=0`. Destroying the source then leaves the copied optimizer referring to a destroyed loss object.
- **Contract:** Inferred ownership/lifetime contract for implicitly supported copy/move operations.
- **Smallest safe fix:** Delete compiled-model copy/move until correct semantics exist; verify direct factory return still benefits from guaranteed copy elision. Then remove the stored reference by passing loss to optimizer execution, or implement explicit rebinding while preserving optimizer state. Test source destruction after relocation under ASan.

### F20 — Medium: global registration retains models and grows on repeated execution

- **Reviewers / confidence:** Architecture; coordinator source check. High; direct retention paths.
- **Evidence:** Variable construction registers an owning copy at `include/variable.hpp:61–62` and `include/session.hpp:51–54`. The default session is a singleton at lines 207–209. `session::bind` appends a placeholder on every call at lines 44–48; `train_on_batch` binds twice per batch (`include/model.hpp:250–252`), and `predict` binds on every invocation (line 352). Ordinary model destruction does not release registry-owned state, and repeated calls add bookkeeping indefinitely.
- **Contract:** Inferred bounded-resource expectation for a fixed model and lifetime isolation between models.
- **Smallest safe fix:** Deduplicate bindings by identity and give parameter registration explicit scoped ownership or pruned weak handles. Ensure optimizers visit only the parameters of their loss/model, rather than every registered variable. Test stable registry sizes and live-state counts over repeated predict/create/destroy cycles. Do not use a global clear that invalidates unrelated models.

### F21 — Medium: public session convenience APIs fail to instantiate

- **Reviewers / confidence:** Readability/simplicity; compiler reproduced by that read-only shard. High.
- **Evidence:** `include/session.hpp:237` copies the default session even though its copy constructor is deleted at line 33; `ceras::run(p)` fails to compile for a placeholder. `tap` at lines 68–70 is const but calls non-const `run` at line 59; calling `session.tap(p)` also fails to compile.
- **Contract:** The documented execution wrapper at lines 228–231 and registration-before-restore intent at lines 65–66.
- **Smallest safe fix:** Bind `auto& ss` in the wrapper and remove `const` from the mutating `tap`. Instantiate public wrappers in compile tests and run the binding/execution/restore workflow with small fixtures.

### F22 — Medium: the documented seed assignment does not reseed the RNG

- **Reviewers / confidence:** Readability/simplicity; coordinator source check. High; complete data-flow evidence.
- **Evidence:** `include/tensor.hpp:26–34` documents `random_seed=42`, but constructs `random_generator` only once from the original seed. Generation at `include/tensor.tcc:831,844,864,874` uses the engine directly. Assigning the seed variable later has no effect. Header-scope `static` also creates per-TU engines.
- **Contract:** Explicit reproducibility promise at `include/tensor.hpp:26–30`.
- **Smallest safe fix:** Provide `seed_random(seed)` that calls the engine's `seed`; define whether the compatibility engine is shared across TUs. Prefer an explicit engine in a later execution context. Test reseed/generate equality and cross-TU behavior, without promising identical distribution output across different standard libraries.

### F23 — Medium: allocating operations claim unconditional `noexcept`

- **Reviewers / confidence:** Readability/simplicity; coordinator source check. High; direct allocation paths.
- **Evidence:** `include/tensor.hpp:292–294` allocates a new shape vector inside `noexcept`. `include/tensor.tcc:203–205` wraps allocating deep-copy with `noexcept`. Placeholder shape operations at `include/place_holder.hpp:73–83` similarly allocate. Allocation failures terminate instead of reaching callers.
- **Contract:** Inferred recoverable allocation/error-handling expectation; no explicit termination policy was found for these APIs.
- **Smallest safe fix:** Remove unconditional `noexcept` from allocating operations and their forwarding call chains. Keep it for provably nonthrowing observers/moves. Offer a separately named borrowed shape view rather than silently changing the lifetime contract of `shape()`. Verify with controlled allocation failure.

### F24 — High: nonzero-start parallel ranges overlap and execute outside their bounds

- **Reviewers / confidence:** Performance and safety; coordinator reproduced. High.
- **Evidence:** `include/utils/parallel.hpp:58` offsets worker slices by `dim_first`, but the caller slice at line 65 omits that offset. On 24 hardware threads, requested range `[1000,1048)` invoked the callback 1,048 times instead of 48, with 954 calls below the requested start. Overlapping writes can cause data races as well as incorrect results.
- **Contract:** Inferred range contract: each index in `[first,last)` executes exactly once.
- **Smallest safe fix:** Include and clamp the offset, using checked partition arithmetic and rejecting reversed ranges. Test exact-once visitation for empty, offset, uneven, and small ranges with controllable worker counts. No TSan result is claimed for this review.

### F25 — Medium: tiny elementwise loops repeatedly create OS threads

- **Reviewers / confidence:** Performance; coordinator source check. High for structural cost; speed impact unmeasured.
- **Evidence:** `include/utils/for_each.hpp:48–52` sends each loop to `parallel`, whose threshold is eight (`include/utils/parallel.hpp:14`) and which creates/joins threads each call (lines 35–41,53–68). Softmax performs two such loops per row (`include/tensor.tcc:1082,1084`). With 24 cores and ten columns, this creates and joins 20 threads per row.
- **Contract:** None; concrete avoidable execution overhead.
- **Smallest safe fix:** Keep small inner loops serial and parallelize enough independent rows once. Expose a minimum-work policy. Measure before choosing a bounded worker pool, and avoid oversubscribing BLAS threads. This report claims no measured speedup.

### F26 — Medium: first CUDA GEMM can launch an unbounded calibration search

- **Reviewers / confidence:** Performance; coordinator source check. High; termination condition directly visible.
- **Evidence:** `include/tensor.tcc:477–494,499–516` grows square matrices by 16 until one timing favors GPU. There is no dimension, allocation, or elapsed-time cap and no no-crossover outcome. Calibration is automatic at lines 528–529, even for a small requested operation.
- **Contract:** Inferred bounded initialization/resource-use expectation; no explicit latency promise exists.
- **Smallest safe fix:** Make tuning explicit, or enforce a time/memory/dimension budget with a defined CPU fallback. Key results by device and scalar type and use warmups plus repeated samples. Test a timing backend in which GPU never wins.

### F27 — High, conditional on concurrent calls: CUDA GEMMs share writable scratch buffers

- **Reviewers / confidence:** Performance; coordinator source check. High for the interleaving defect; GPU execution not tested.
- **Evidence:** `include/backend/cuda.hpp:401–407` supplies every GEMM with the same singleton operand/result buffers. Growth frees the old storage at lines 308–312. Overlapping calls can replace another call's operands or free its storage. Plain global threshold initialization at `include/tensor.tcc:528–529` also lacks synchronization.
- **Contract:** No explicit thread-safety guarantee was found. The violated inferred expectation is safe independent operations on independent caller buffers. This finding applies when calls overlap; it does not claim a single-threaded reproduction.
- **Smallest safe fix:** Serialize the entire reserve/copy/GEMM/copy transaction and initialization, then introduce a context owning device, stream, handle, and scratch storage. Document the concurrency contract. CPU cache/RNG/session globals need the same ownership audit before advertising concurrent use.

### F28 — Medium: CI lacks a numerical regression oracle

- **Reviewers / confidence:** Tests; coordinator ran the utility suite. High; direct CI/test evidence.
- **Evidence:** `.github/workflows/c-cpp.yml:21–24` runs `test_ci` and MNIST. `test/ci.cc:5–6` includes only enumerate and buffered-allocator suites. `test/mnist.cc:158–161` prints error rate and returns zero without an accuracy requirement. The locally built CI executable passed 11,934,000 assertions in only two cases.

- **Smallest safe fix:** Turn tiny examples into deterministic assertions and register actual execution in CI. Add independent scalar/reference recurrences and numerical gradients. Keep seeded MNIST as a slower integration gate with a measured tolerance and accuracy/loss requirement, not the sole numerical exercise.

### F29 — Medium: GEMM parity tests assume an enabled CUDA backend

## Triage notes and boundaries

The architecture shard initially described compiled-model freezing as a runtime failure. The coordinator found that ordinary operator graphs first fail to compile, so that claim was narrowed to F32. The split trainability metadata remains a source-supported follow-up, not a runtime result claimed here.

The readability shard also found `place_holder::operator>` implemented with `<` at `include/place_holder.hpp:119–121`. Fix this low-impact defect in the API cleanup and test all comparison relationships; an ID-based `<=>` can remove duplication. Additional optimizer source discrepancies—SGD's reversed Nesterov selection (`include/optimizer.hpp:61–62`) and Adam's first two plain-SGD steps (lines 297–300)—belong in the reference-recurrence audit, even after F15/F16 are fixed. These are backlog observations, not extra items in the accepted-finding count.

No finding asserts that shallow tensor copies are inherently wrong: sharing may be intentional. The migration must make aliasing explicit and ensure backward functions do not unexpectedly mutate caller gradients. Likewise, this review does not establish complete thread safety, parser security, or CUDA correctness.

## Executable upgrade plan


ASan and TSan need separate builds. Add GCC/Clang C++20 required lanes, C++23 lanes for the chosen libraries, and an informational C++26 lane until every required feature is available. Run both assertions-enabled and `NDEBUG` configurations. Add MSVC/LLP64 compile coverage if Windows remains supported; current use of `unsigned long` must not silently encode 64-bit-size assumptions. Use portable release flags by default: current `-ffast-math`, `-Ofast`, and `-march=native` should be explicit opt-ins, with fast-math results compared to a strict reference lane.

For gradients, start with tiny double tensors and central differences, an initial step near `1e-6`, and scale-aware absolute/relative tolerances around `1e-6`/`1e-4`; calibrate per operation and avoid nondifferentiable points. Cover all activations, broadcast paths, reductions, convolution/pooling, regularizers, and losses. Separate tests should specify NaN, infinity, empty tensors, zero extents, rank errors, aliasing, and noncontiguous/view behavior. Reference implementations must be independent of the optimized code being tested.

Per-PR fuzz smoke should be time-bounded, for example 60 seconds per parser target, with longer seeded nightly runs and retained crash inputs. Monitor supported object-lifetime counts rather than assuming the process RSS must immediately shrink: allocators and pools can retain freed capacity legitimately.

## Modern C++ adoption decisions

Apply RAII, explicit ownership, and bounded range interfaces first, consistent with the [C++ Core Guidelines](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines). The recommendations below are proposals for this library, not claims that newer syntax supplies automatic memory safety.

| Level | Apply here | Guardrail |
| --- | --- | --- |
| C++20 now | `std::vector` or another RAII owner for storage; `std::span<const T>`/`std::span<T>` for contiguous kernel arguments; concepts for supported scalar/backend types; ranges for simple traversal; `std::jthread` where thread lifetime needs automatic joining; ID-based comparison. | A span is borrowed and does not extend lifetime. Ordinary indexing is not a universal checked-access guarantee. Explicitly validate public indices, products, shapes and aliasing; `jthread` does not create a pool or solve shared-state races. |
| C++23 selectively | `std::expected<T,Error>` for recoverable I/O/configuration results, `std::mdspan` for fixed-rank strided kernel views, `std::scope_exit` for restoring phase/backend state. | Choose one coherent error policy. `mdspan` does not own data; its rank is a type property, so arbitrary runtime-rank tensors still need a descriptor/dispatch layer. Keep ownership and shape validation outside the view. See the [multidimensional-access specification](https://eel.is/c++draft/mdspan.overview). |
| C++26 bounds/container support | Use `std::span::at` when available for checked access; consider `std::inplace_vector` for explicitly bounded rank metadata. | `inplace_vector` has fixed capacity and no heap spill; it is not a transparent replacement for unbounded tensor rank. Reject excess rank or retain dynamic storage. See [span access](https://eel.is/c++draft/span.elem) and [inplace_vector](https://eel.is/c++draft/inplace.vector.overview). |
| C++26 numerical facilities | Evaluate `<linalg>` adapters around `mdspan` and `<simd>` for measured kernels. | Retain backend parity tests and validate layouts, strides, types and precision. A standard API does not promise a faster implementation than tuned BLAS. See [linear algebra](https://eel.is/c++draft/linalg) and [SIMD](https://eel.is/c++draft/simd). |
| C++26 contracts | Express internal preconditions where the toolchain supports them. | Keep unconditional external-input validation. Contract evaluation can use ignore/observe/enforce modes; it is not a replacement for parsing/error handling. See [contract evaluation semantics](https://eel.is/c++draft/basic.contract.eval). |
| C++26 execution/reflection | Consider senders/receivers only if explicit asynchronous CPU/GPU execution becomes a product requirement. Consider reflection later for repetitive metadata/serialization. | Neither is needed to repair current ownership and gradients. Avoid making immature support a prerequisite for the safety work. See [execution facilities](https://eel.is/c++draft/exec). |

At review time, official [GCC language support](https://gcc.gnu.org/projects/cxx-status.html) and [Clang language support](https://clang.llvm.org/cxx_status.html) list incomplete/experimental C++26 support. Language mode acceptance is not library availability; consult the selected library's implementation table, such as [libstdc++ status](https://gcc.gnu.org/onlinedocs/libstdc++/manual/status.html), and compile a probe for each actual API. Pin compiler/library versions in CI and use feature-test macros plus configure-time compilation checks. Do not assume proposed safety profiles are an available portable guarantee.

Keep graph definition separate from execution records: a model owns graph topology/parameter identity; an execution context owns cache generation, RNG, training phase and backend resources; an optimizer owns its typed state. Preserve expression-template APIs initially through adapters. Use standard containers before introducing `std::pmr` pools; a pool resource must outlive all allocations, be appropriate for the concurrency model, and have measured benefit. Name deep copies and borrowed/shared views explicitly and test their lifetime/aliasing rules before changing existing copy semantics.

For performance acceptance, record compiler flags, backend versions, CPU/GPU identity, worker count, matrix shape/type and warmup policy. Benchmark elementwise/softmax sizes around the current threshold and CPU count; benchmark square, tall, wide, and vector-like GEMMs with all transpose combinations, cold/warm starts and repeated weights. Record transfer bytes and peak host/device memory. Current CUDA GEMM copies both operands and the result every call (`include/backend/cuda.hpp:404–406,437`); persistent device tensors are a later measured optimization, not a safe first patch.

### Reproducing the focused runtime checks

Save the following as `/tmp/ceras-review-probe.cc`. It intentionally exercises the unchanged defects and is not a replacement for permanent regression tests.

```cpp
#include "ceras.hpp"
#include "utils/imageio.hpp"
#include <atomic>

int main(int argc, char** argv) {
    using ceras::tensor;
    std::string mode = argc > 1 ? argv[1] : "math";
    if (mode == "gc") {
        ceras::cached_allocator<float> a;
        auto p = a.allocate(4); a.deallocate(p, 4);
        ceras::get_memory_cache().gc();
        auto q = a.allocate(4); q[0] = 42; a.deallocate(q, 4);
    } else if (mode == "read") {
        tensor<float> x;
        std::istringstream input("1\n1 2 3\n");
        ceras::read_tensor(input, x);
    } else if (mode == "image") {
        tensor<unsigned char> x({2, 2}, static_cast<unsigned char>(1));
        auto y = ceras::imageio::imresize(x, {4, 4});
        std::cout << y.size() << '\n';
    } else if (mode == "dag") {
        auto x = ceras::variable{tensor<float>({2}, 1.0f)};
        auto r = ceras::relu(x);
        auto y = ceras::sum_reduce(r + r);
        auto result = ceras::get_default_session<tensor<float>>().run(y);
        y.backward(ceras::ones_like(result));
        std::cout << x.gradient() << '\n';
    } else if (mode == "parallel") {
        auto n = std::thread::hardware_concurrency();
        std::atomic<unsigned long> count{0}, below{0};
        ceras::parallel([&](unsigned long i) {
            ++count; if (i < 1000) ++below;
        }, 1000UL, 1000UL + 2*n, 0);
        std::cout << "cores=" << n << " calls=" << count
                  << " expected=" << 2*n << " below_start=" << below << '\n';
    } else {
        auto x = ceras::variable{tensor<float>({1, 2}, 0.0f)};
        auto y = ceras::softmax(x);
        auto result = ceras::get_default_session<tensor<float>>().run(y);
        y.backward(ceras::ones_like(result));
        std::cout << "softmax gradient (expected zeros): " << x.gradient();
        auto a = ceras::variable{tensor<float>({2, 3}, 1.0f)};
        auto b = ceras::mean_reduce(a);
        auto m = ceras::get_default_session<tensor<float>>().run(b);
        b.backward(ceras::ones_like(m));
        std::cout << "mean gradient (expected 1/6): " << a.gradient();
        std::cout << "max (expected -1): "
                  << ceras::max(tensor<float>({1, 2}, {-2.0f, -1.0f}), 1);
    }
}
```
