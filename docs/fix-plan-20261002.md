# Ceras finding remediation plan

Status: W01–W13 implemented and verified in the working tree on 2026-10-02. W14 evaluated through a C++26 feature probe; optional API adoption remains deferred. See [implementation and evidence](implementation-20261002.md) and [migration guidance](migration-20261002.md).

Source: [review-20261002.md](review-20261002.md), covering `main` at `48fe97c1ef30181cffa0446af8f6831140c9963d`.

This plan closes all 32 accepted findings through 13 implementation steps, followed by an optional modern-library adoption step. It expands the review's broad phases into changes that can be implemented and verified separately. Finding IDs and evidence remain in the review; the table below is the closure checklist.

## Working decisions

1. Keep C++20 as the supported baseline while repairing behavior. Introduce C++23/C++26 features only after the repair gates pass, using compiler and library feature probes.
2. Use standard owning storage. Retain shallow tensor element-sharing semantics initially, but make structural resizing preserve every alias's shape/storage invariant. Do not silently turn every tensor copy into a deep copy.
3. Retire the custom allocation algorithms from the supported implementation. Preserve the allocator template names as deprecated standard-allocator compatibility adapters where feasible; the buffered byte capacity becomes a deprecated, ignored performance hint. Remove the internal memory-cache implementation. This deliberately gives up unmeasured caching and inline-storage optimizations to close their safety defects.
4. Preserve public signatures where safe. Invalid shapes/indices use documented exceptions; allocation failure propagates; stream extraction reports parse failure through stream state and honors its exception mask. Path-based loaders provide contextual exceptions. Assertions remain for internal invariants and never replace external-input validation.
5. An operation's backward pass differentiates its actual forward result. Losses own their reduction factor; optimizers consume the resulting gradient without another implicit batch-size normalization. Update examples and migration guidance with this behavior change.
6. Graph nodes share identity and topology; an execution context owns forward records, generation, RNG and training phase. Optimizers own typed state and an explicit parameter set. Default-session convenience APIs remain adapters to this ownership model.
7. Initially serialize use of the default execution context and shared CUDA resources. Independent explicit contexts become the supported concurrency boundary only after isolation tests pass. Internal parallel kernels may operate on proven disjoint ranges.
8. Each fix carries a regression that demonstrates the original failure. Do not merge expected-failure markers as permanent substitutes for repaired behavior. A finding is closed by its acceptance evidence, not by a refactor's size or a green training demo.

The compatibility adapters in decision 3 must honor standard allocator construction, destruction, alignment and propagation semantics. They are not wrappers around the defective cache. Internal calls such as `get_memory_cache().gc()` are removed; dependent examples/tests migrate to observable allocation/lifetime contracts. CUDA pinned-memory ownership moves to the backend boundary instead of being hidden in a tensor shape allocator.

## Implementation steps

### W01 — Make tests and backend selection reproducible

**Files:** `Makefile`, new `CMakeLists.txt`/`CMakePresets.json`, `.github/workflows/c-cpp.yml`, maintained tests under `test/`.

- Register a supported test manifest rather than globbing every historical `.cc` example. Separate fast unit tests, dataset integration, image tests, and optional CUDA tests.
- Keep the existing Makefile usable: fix the `CBLAS` conditional, remove stale targets or restore sources that are deliberately supported, and make test execution explicit.
- Add a scalar GEMM oracle that runs without CUDA. Enable CBLAS/CUDA parity only when the respective backend is built; unavailable hardware must be visible as skipped, not recorded as a pass.
- Add CMake interface/core and test targets, strict floating-point defaults, and separate backend options. W04 introduces the compiled image target.
- Build test artifacts outside tracked binary/object directories. Verify the maintained targets from a clean checkout/export that cannot see today's untracked files.

**Acceptance:** A clean CPU checkout configures, builds, and executes registered tests. CPU GEMM tests cover float/double, nonsquare shapes and all transpose combinations. `CBLAS=1` enables the actual backend or fails clearly if unavailable. Every advertised maintained target has a tracked source. Introduced regression tests for other findings travel with their fix; W01 does not claim numerical coverage is complete.

### W02 — Replace unsafe storage and establish tensor invariants

**Files:** `include/utils/{vector,buffered_allocator,cached_allocator}.hpp`, `include/tensor.hpp`, `include/tensor.tcc`, allocation/shape call sites.

- Replace the custom vector's ownership implementation with standard storage, retaining a small adapter only where existing resize/reset behavior requires it. Support the scalar types used by the library explicitly; do not rely on raw zeroed bytes to construct arbitrary `T`.
- Replace the custom allocators as described in the working decisions. Remove the cache's stale-pointer, alignment, multiplication and shutdown-lifetime paths together. Cover allocator adapters in standalone-header and two-TU tests once W04 permits them.
- Add shared helpers for checked extent products, byte counts, offsets and narrowing to backend integer types. Use `std::size_t` for storage sizes. Check `max_size()` and reject impossible requests before allocating.
- Specify empty/default tensor, scalar and zero-extent behavior. Preserve existing valid public representations where possible; reject ambiguous operations explicitly.
- Allocate and validate before replacing existing state. Structural resize of shared storage must detach or update a shared descriptor consistently; choose detachment so sibling tensor shapes remain valid. Keep ordinary shared element mutation behavior explicit.
- Audit allocating methods and forwarding call chains for false `noexcept`. Avoid a partial fix where an inner exception still crosses an outer unconditional `noexcept` boundary.

**Acceptance:** Controlled allocation failure leaves owners valid and destructible; move/self-move and repeated resize balance live allocations; supported over-aligned storage is correctly aligned. Overflow boundary tests reject inputs without huge allocation attempts. Copy/resize tests preserve sibling invariants. Allocation errors reach the caller where specified. ASan+UBSan pass in Debug and `NDEBUG` builds. Removing a dangerous implementation closes its finding only after all supported call sites and public adapters stop using it.

### W03 — Validate input before changing live state

**Files:** `include/tensor.tcc`, `include/session.hpp`, `include/dataset.hpp`.

- Parse tensor shape and payload into temporary storage. Validate complete syntax, counts, extent products, allocation limits and stream status before committing.
- Restore session parameters transactionally: validate IDs and all tensor records before replacing any live parameter. An unknown ID or a malformed later record must not leave a partially restored model.
- Share one IDX parser between MNIST and Fashion-MNIST. Validate big-endian header fields, magic, dimensions, sample counts, exact lengths, matching image/label counts and label range.
- Add explicit parser size/rank/allocation limits with documented defaults and overrides. Bound decompression output in the session restore path so compressed inputs cannot bypass those limits.

**Acceptance:** Oversized/truncated/malformed tensor streams, unknown session IDs, short IDX headers, inconsistent counts, trailing image bytes and label 255 fail cleanly in both build modes. Failed restores preserve all prior parameter values. Tiny valid fixtures round-trip. Fuzz targets terminate within configured resource limits and remain sanitizer-clean.

### W04 — Repair image buffer contracts and header integration

**Files:** `include/includes.hpp`, `include/utils/imageio.hpp`, new image implementation source/target, consumer examples.

- Move STB implementations into exactly one optional compiled image-I/O target. Keep core numerical headers usable without image implementation definitions. Update umbrella-header and linking instructions explicitly; this is an integration change for users of image functions.
- Validate image ranks, channel counts, dimension conversions and exact element counts before calling STB. Use one channel for rank-two grayscale and check resize return values.
- Dispatch HDR through actual float storage before byte normalization. Restrict direct encoders to compatible pixel types and define byte-to-float conversion behavior.
- Use RAII for library-owned image buffers so allocation or conversion exceptions cannot leak them.

**Acceptance:** Two independent consumer translation units link and run. Core consumers need no image library; image consumers link one implementation. Grayscale/color resize and byte/float HDR fixtures pass ASan+UBSan and decode to expected dimensions/values. Invalid ranks/channels fail before external calls. Preserve a documented image dimension order rather than silently transposing existing data.

### W05 — Fix range partitioning before relying on parallel numerical tests

**Files:** `include/utils/parallel.hpp`, `include/utils/for_each.hpp`.

- Add the missing start offset and use one checked partition calculation for workers and the caller.
- Handle empty/reversed ranges, uneven divisions and unknown hardware concurrency explicitly. Make worker count injectable in tests.
- Ensure all started workers are joined if creation or a callback fails. Propagate a recorded exception after joining; define the supported callback contract.

**Acceptance:** An exact-once counter covers every requested index and no others for worker counts 0, 1, 2 and larger than the work size. Include the `[1000,1048)` regression, small/uneven ranges and near-limit arithmetic. Serial and parallel output match; disjoint-write tests pass TSan. Thread creation optimization waits until W13.

### W06 — Make forward caches complete and execution-scoped

**Files:** `include/operation.hpp`, `include/session.hpp`, graph/context helpers.

- Store saved operands and output as one forward record keyed by node identity and execution generation. Cache hits return the complete record.
- Preserve the forward record through backward. Starting optimizer execution must not invalidate the loss's required saved inputs; distinguish a new forward pass from an optimizer step.
- Define repeated forward/backward behavior and reject backward without a valid matching forward record.
- Ensure backward outputs have independent storage when a function would otherwise mutate a borrowed upstream gradient or a sibling branch's data.

**Acceptance:** `sum_reduce(relu(x)+relu(x))` with a reused node passes value/gradient checks. Test diamond graphs, shared binary nodes, weighted sibling branches, changed inputs between runs, repeated execution and missing/stale forward records. Caller input/upstream tensors remain unchanged where the API promises read-only use. ASan+UBSan report no invalid access.

### W07 — Correct mathematics and settle normalization once

**Files:** `include/activation.hpp`, `include/operation.hpp`, `include/loss.hpp`, `include/tensor.tcc`, normalization-related optimizer code.

- Implement the full softmax Jacobian-vector product per row.
- Divide mean backward by the same element count as forward. Apply identical reduction factors to cross-entropy forward/backward.
- Correct ELU and the implemented GELU approximation's derivatives, including multiplication by upstream gradient.
- Initialize maximum reductions from a valid element or a documented identity; specify empty/NaN/infinity behavior.
- Remove implicit optimizer batch-size scaling in the same integration change that corrects averaged-loss gradients. Keep a compatibility constructor if useful, but deprecate the argument's old normalization effect and update examples. Do not release half of this convention change.
- Add gradient checks for neighboring activation/reduction implementations to catch copied formula defects without expanding into an unrelated architecture rewrite.

**Acceptance:** Constant-sum softmax has zero gradient; every differentiable operation has zero output gradient for zero upstream and is linear in upstream. Central differences pass for tiny double tensors with scale-aware tolerances and inputs away from nondifferentiable points. Duplicating an identical batch preserves a mean-loss parameter gradient and its update. Negative-only maximum returns the correct value. Document changes to training learning-rate interpretation.

### W08 — Give each optimizer its own typed state

**Files:** `include/optimizer.hpp`, `include/variable.hpp`, optimizer/model construction.

- Replace variable-owned untyped slot vectors with typed state owned by an optimizer instance and keyed by stable parameter identity. State records validate parameter shape.
- Repair Adadelta's independent accumulators. Test SGD/momentum/Nesterov, Adam, Adagrad, RMSprop and Adadelta against independent scalar recurrences, including initial steps.
- Resolve the review's additional Nesterov branch and Adam warmup discrepancies as part of those recurrence tests; avoid preserving undocumented algorithm changes accidentally.
- Restrict updates to the loss/model's parameter set. Specify reset/resume behavior when changing optimizer, shape or trainability.

**Acceptance:** SGD→Adam, Adam→SGD and two optimizer instances on shared parameters never reuse incompatible state or access missing slots. Several scalar steps match a hand-derived oracle with changing gradients. Unrelated registered variables remain unchanged. State reset and shape-change behavior are tested. Batch normalization agrees with W07.

### W09 — Repair compiled-model lifetime and registration ownership

**Files:** `include/model.hpp`, `include/session.hpp`, `include/variable.hpp`, traversal/accessor helpers.

- First delete unsafe compiled-model copy/move operations and test factory construction. Then remove the optimizer's stored reference into the model by passing the loss into execution; retain noncopyability until deliberate copy/relocation semantics are implemented and tested.
- Deduplicate placeholder binding by stable identity. Give explicit contexts scoped ownership; default-session registration uses nonowning handles with pruning, so destroying user models releases their parameter state.
- Replace obsolete direct operator-member accesses with a shared traversal utility using current accessors. Support both freeze and model composition through that traversal.
- Put trainability and other per-parameter shared metadata in shared parameter state; separate per-execution regularizer bookkeeping from permanent parameter metadata.

**Acceptance:** Supported model relocation followed by source destruction passes ASan; unsupported operations fail at compile time. Freeze after training prevents every subsequent parameter update, including through graph copies. Composition and traversal compile and execute. Thousands of binds/predictions keep registration size bounded, and create/train/destroy cycles return live parameter counts to baseline without clearing another model's state.

### W10 — Repair public convenience APIs and seeding

**Files:** `include/session.hpp`, `include/tensor.hpp`, `include/tensor.tcc`, `include/place_holder.hpp`, documentation/examples.

- Fix `ceras::run` to reference its session and make `tap`'s mutating contract explicit. Add public-surface compile tests, not only tests of internal primitives.
- Implement `seed_random(seed)` against the actual context engine. Provide one deliberate default-context behavior across translation units and update the old seed-assignment documentation.
- Fix placeholder ordering and consolidate equivalent relational operators where this preserves identity semantics.
- Finish API documentation for aliases, error propagation, lifetime, phase changes and supported concurrency.

**Acceptance:** Public bind/run/tap/restore workflows compile and run. Reseed/generate/reseed/generate repeats within the supported implementation, including calls from two translation units. Independent explicit RNG contexts do not perturb each other. Placeholder comparisons obey reversal/equality laws. Do not promise identical distribution output across different standard libraries.

### W11 — Bound CUDA setup and isolate backend state

**Files:** `include/backend/cuda.hpp`, GEMM dispatch in `include/tensor.tcc`, execution-context configuration.

- Serialize the whole shared CUDA reserve→input copy→GEMM→output copy transaction as the initial repair. Protect handle creation and tuning state consistently; a lock only around allocation is insufficient.
- Make calibration explicit rather than an unbounded side effect of first GEMM. Add dimension, memory and elapsed-time caps and a defined no-crossover fallback.
- Move device, stream, handle, scratch capacity and tuning results into an RAII backend context. Key tuning by device and scalar type; validate all dimension products/narrowing before dispatch.
- Expose explicit CPU/CBLAS/CUDA selection so tests do not depend on timing-based routing.

**Acceptance:** A fake timing backend where GPU never wins exits within budget. Forced interleavings verify scratch ownership; real concurrent calls, growth during another call, multiple shapes/types and backend errors are checked on CUDA hardware. Host-side mocks do not close the GPU validation requirement. Until hardware evidence exists, mark F27 as implemented but awaiting verification and retain serialized/experimental CUDA scope.

### W12 — Make regression coverage a release requirement

**Files:** CI workflows, CMake presets/test labels, numerical/property/fuzz fixtures.

- Run small deterministic numerical tests on every pull request with GCC and Clang, Debug and Release/`NDEBUG`, strict floating-point semantics and fresh builds.
- Add ASan+UBSan in separate Debug and `NDEBUG` configurations; run TSan separately for the supported concurrency surface. Enable leak checks where the runner supports them and report unavailable instrumentation honestly.
- Register CBLAS parity and a scheduled/hardware CUDA lane. Add supported public-header, two-TU and compatibility compile tests.
- Keep MNIST as a slower seeded integration test with an explicit measured loss/accuracy criterion. Store tiny fixtures in tests; network/dataset availability must not determine whether core regressions run.
- Add bounded parser fuzz smoke per pull request and longer nightly runs. Save failing seeds, inputs, compiler/backend versions and logs.
- Verify the gate itself by temporarily injecting representative faults in isolated worktrees: zero a gradient, skip an update, and disable a validation check. The relevant checks must fail for the intended reason; do not retain those mutations.

**Acceptance:** Every mandatory test executes and can fail CI. All F01–F24 and F26–F32 closure tests pass in their applicable configurations, with explicit hardware limitations recorded. No permanent skips/expected failures conceal accepted defects. CI distinguishes unit coverage from dataset demonstrations and from hardware tests.

### W13 — Reduce thread overhead without changing results

**Files:** `include/utils/parallel.hpp`, `include/utils/for_each.hpp`, softmax kernels, benchmark targets.

- Make tiny inner loops serial and parallelize sufficiently large groups of independent rows once. Expose a minimum-work setting and prevent nested oversubscription with threaded BLAS.
- Capture a baseline before introducing a pool. Add a bounded reusable pool only if target workloads justify its lifetime/exception complexity.
- Benchmark widths around 8 and hardware concurrency, multiple row counts, float/double, serial/parallel modes and warm/cold execution. Record threads created, allocations, elapsed-time distribution and peak memory.

**Acceptance:** Tiny softmax rows no longer create threads per elementwise pass. Values and gradients remain within established tolerances and sanitizer tests still pass. Report fixed-hardware before/after results, including regressions. Define a provisional noise budget of 5% in median runtime across repeated runs; investigate rather than automatically reject changes within measurement noise. Do not claim a universal speedup.

### W14 — Adopt modern facilities after the behavior is stable

Use the [review's Modern C++ adoption decisions](review-20261002.md#modern-c-adoption-decisions) as the feature shortlist. Introduce bounded `span` interfaces and standard RAII immediately where W02–W11 need them; later evaluate C++23 `expected`, `mdspan` and scope guards through compatibility facades. Evaluate C++26 checked access, fixed-capacity containers and numerical facilities only when configuration probes verify the exact compiler/library APIs.

No correctness fix depends on C++26, reflection, modules, senders/receivers or a new tensor framework. Change the minimum language version only in a separate documented compatibility release. Contracts supplement internal invariants; they never replace unconditional parsing and shape checks.

## Validation commands to introduce in W01

The following presets and labels are now implemented; they were unavailable in the reviewed commit. Configure the presets with tests enabled, strict FP, the required compiler and the corresponding sanitizer flags. Every CTest invocation must fail if its selected test set is empty.

```sh
rtk proxy cmake --preset cpu-debug
rtk proxy cmake --build --preset cpu-debug
rtk proxy ctest --preset cpu-debug --output-on-failure --no-tests=error

rtk proxy cmake --preset cpu-release
rtk proxy cmake --build --preset cpu-release
rtk proxy ctest --preset cpu-release --output-on-failure --no-tests=error

rtk proxy cmake --preset asan-ubsan-release
rtk proxy cmake --build --preset asan-ubsan-release
rtk proxy ctest --preset asan-ubsan-release --output-on-failure --no-tests=error

rtk proxy cmake --preset tsan
rtk proxy cmake --build --preset tsan
rtk proxy ctest --preset tsan -L concurrency --output-on-failure --no-tests=error
```

Also introduce `asan-ubsan-debug`, `cblas-release` and `cuda-release` presets as their steps become available. CUDA tests must report hardware execution separately from host mocks. Add a `fuzz-smoke` target with fixed budgets and a `benchmarks` target that records results but does not substitute for correctness tests.

## Completion and handoff

For each step, record the reviewed commit, failing-before/passing-after regression evidence, compiler/build options, applicable sanitizer results and compatibility changes. Run the focused regression first, then the affected numerical/backend tests and required CI gates. Further broad test runs are warranted by additional changes or unresolved failures, not by repetition alone.

The remediation is complete when all 32 checklist entries have closure evidence and supported configurations pass. CUDA hardware absence leaves F27 awaiting verification; it is not an implicit pass. A CPU-only release can explicitly exclude CUDA, but that scope decision does not mean all findings have been fixed.

W01–W13 and the applicable CPU/GPU gates are complete in the working tree. Optional modernization remains a separate compatibility task. The local validation does not claim the GitHub-hosted workflow has already executed.
